# Phase 6 — global integration

Turns Frost from "a session beside Omarchy" into a system that installs and
boots on its own, on a **fresh CachyOS Minimal base**. The in-place Omarchy
cutover of the master plan's Phase 8 does not apply: the chosen path is a clean
install via `bootstrap-cachyos`, and AUR uses `paru` (no hardened builder or
root helper — the master plan's "Track B" is dropped by decision, 2026-08-30).

## Out of scope: initramfs, splash and bootloader

Decision, 2026-08-30: the bootstrap does not touch `mkinitcpio.conf`, does not
regenerate an initramfs and does not read or write a bootloader. Frost ships no
Plymouth theme, so the hook it used to add would only have surfaced the CachyOS
splash that is already configured; the base's boot path is left as CachyOS built
it, and `install-contract` now fails if the script mentions any of it.

## Provider pinning

The first install attempt died on `jack2 and pipewire-jack are in conflict`.
`ffmpeg`, `mpv`, `obs-studio` and `portaudio` depend on the virtual `jack`, which
`jack2` and `pipewire-jack` both provide; alpm resolves depth-first in manifest
order, reaches `jack` through `ffmpegthumbnailer` long before it reaches
`pipewire-jack`, and `--noconfirm` takes the first candidate. The two then meet as
targets of one transaction, which `--ask=4` cannot resolve.

`FROST_PROVIDERS` settles every ambiguous virtual in the closure as its own
transaction, before anything that needs one: `jack` → `pipewire-jack`,
`pipewire-session-manager` → `wireplumber`, `opengl-driver` → `mesa`,
`vulkan-driver` → `vulkan-radeon` (the default was an NVIDIA stack), `ttf-font` →
`ttf-dejavu`, `tessdata` → `tesseract-data-eng`, `netcat` → `openbsd-netcat`.
`test/resolve-plan` resolves the whole set against the live CachyOS repositories
and fails if any rejected provider reappears.

## What the first clean installs cost, and what now guards it

Four defects took the VM from "installs" to "installs correctly". Three of them
share one shape — something that worked on the development machine only because
its environment happened to supply what Frost never declared — and they are
recorded here because the next port to a different base will meet the same class
again.

| Symptom | Cause | Guard |
|---|---|---|
| `jack2 and pipewire-jack are in conflict` | alpm resolves depth-first and `--noconfirm` takes the first provider of a virtual; `jack` reached through `ffmpeg` long before `frost-meta`'s `pipewire-jack` | `FROST_PROVIDERS` installed as its own transaction; `test/resolve-plan` resolves the whole set against the live CachyOS repositories |
| Black screen, no greeter, `sddm-helper exited with 127` | the theme's `metadata.desktop` lacked `QtVersion=6`, so SDDM ran the Qt5 greeter against Qt5 libraries Frost never installs | `settings-contract` requires `QtVersion=6` and `Type=sddm-theme` |
| Empty session, `quickshell` exit 255 | the shell imports `Qt5Compat.GraphicalEffects` → `qt6-5compat`, declared nowhere; present on the dev machine only through `qca-qt6` | `validate-package-config` maps every QML namespace the shell imports to a declared dependency and fails on an unmapped one |
| All 15 AUR packages fail, `sudo: a password is required` | **sudoers ordering**: sudo applies the *last* matching rule and reads `/etc/sudoers.d` in filename order, and the CachyOS installer leaves `10-installer` with `%wheel ALL=(ALL) ALL` | the drop-in is `zz-frost-bootstrap` so it sorts last; `install-contract` pins the name |

The QML that produced two of those failures had no test reading it at all;
`test/qml-contract` now parses all 33 files the shell and the greeter ship.
